# gofs

参照 [sigoden/dufs](https://github.com/sigoden/dufs) 的设计，用 Go 重写的一个实用文件服务器，
并**额外实现了压缩包在线解压**。

单二进制、零第三方依赖（只用 Go 标准库）、内嵌前端，`go build` 出来直接就能跑。

## 特性

**基础能力（对齐 dufs）**

- 静态文件服务，目录浏览支持 HTML / JSON / 纯文本三种视图
- 上传：拖拽上传、**整目录上传（保留层级）**、表单上传、`PUT` 直传、
  `X-Update-Range: append` 追加续传，
  并**默认把「传到根目录」的文件按 年/月/日 三级目录自动归档**
  （子目录原地放；可关闭、可自定义布局、可单次覆盖）
- 删除、新建目录（`MKCOL`）、移动 / 重命名（`MOVE`）
- 递归搜索（`?q=`）
- 目录打包下载为 zip（可选压缩级别）：**不勾选就打包整个目录，
  勾选了就只打包所选**，选中的目录会连同内容一起递归打包
- 单文件下载支持 HTTP Range 断点续传、`?hash` 取 SHA-256
- 基于路径的账号权限控制（`user:pass@/dir:rw,/dir2`），最长前缀匹配，
  页面走 **HTTP Basic 认证**（自带登录框，不弹浏览器原生对话框）
- **页面上的用户管理**：新建账号、按路径分配只读 / 读写权限、改密码、删除；
  密码只存 PBKDF2 摘要，落盘 `users.json`，与启动参数里的账号合并使用
- 隐藏路径 glob、访问路径前缀、CORS、HTTPS、unix socket
- **手机端交互适配**：触摸目标 ≥40px、无 hover 依赖、操作收进「更多」菜单、
  阻断 iOS 输入框自动缩放（详见下文）
- **运行期服务设置**：登录后可在页面上直接**切换服务根目录**、**调整单文件上传上限**，
  改完立刻生效、不用重启（受 `--no-root-switch` / `--root-allow` 约束，详见下文）
- **面向大文件与恶意使用的防护**：流式传输（内存与文件大小无关）、
  「无进展」超时（慢速大文件不被误杀）、断点续传、CSRF / 暴力破解 /
  慢速攻击 / 资源耗尽防护、存储型 XSS 与日志注入防护（详见下文）
- 自定义日志格式（`$remote_addr` `$status` `$http_user_agent` …）
- 可替换的自定义前端资源（`--assets`）
- 内嵌 SPA / index.html 渲染模式（`--render-index` / `--render-try-index` / `--render-spa`）

**在线文本编辑**

- 支持 txt / markdown / html / json / xml / yaml / toml / ini / csv 以及各语言源码
- 点文件名直接进编辑器；行号、Tab 缩进、回车自动续缩进、`Ctrl/⌘ + S` 保存
- **Markdown 渲染预览**（自研渲染器，支持标题/列表/表格/代码块/引用/任务列表）
- **HTML 沙箱预览**、**JSON 格式化与着色**、**XML 结构校验**
- 保存时用**内容摘要做乐观锁**，文件被别人改过会提示而不是静默覆盖
- 保留原文件的 **CRLF/LF 换行风格**与 **UTF-8 BOM**，不会把整份文件的换行都改掉
- 二进制文件、超大文件、UTF-16 编码一律拒绝，避免改坏文件

**上传密钥**

- 给脚本 / 第三方的最小权限凭证：**只能上传**，不能读、删、改、解压
- 可限定目标目录、可设有效期（1 小时 ~ 永不过期）、可随时撤销
- 明文只在创建时显示一次，服务端只存 SHA-256 摘要
- 创建者的权限是上限：只对 `/docs` 有写权限的账号签不出覆盖全盘的密钥

**在线解压（本项目的增量）**

- 支持 `zip` / `tar` / `tar.gz` / `tgz` / `gz`，按文件头嗅探而非只看扩展名
- **内容预览**：不发请求落盘，直接在网页里列出压缩包清单，并可流式取出单个文件
- **在线解压**：解压到服务端磁盘，通过 SSE 实时推送进度（当前条目 / 文件数 / 字节数 / 跳过数）
- 安全防护：Zip Slip、软链逃逸、解压炸弹、权限位提权
- 目录列表里自动给压缩包打「可解压」标记

## 快速开始

```bash
# 构建
go build -o gofs .

# 以只读模式服务当前目录
./gofs

# 服务指定目录，并开放全部操作（含在线解压）
./gofs -A ./data

# 明确只开解压，不开上传删除
./gofs --allow-extract ./uploads

# 需要账号密码：admin 全目录读写，guest 只读
./gofs -a admin:123@/:rw -a guest:guest@/ -A ./data

# 只开在线编辑，不开上传删除
./gofs --allow-edit ./docs

# 完整示例：鉴权 + 编辑 + 解压 + 密钥
./gofs -A -a admin:123@/:rw -b 127.0.0.1 -p 5000 ./data
```

启动后会打印当前生效的配置：

```
gofs 0.1.0
  监听      : http://127.0.0.1:5000
  服务目录  : /home/me/data
  权限      : upload=on edit=on delete=on search=on archive=on extract=on keys=on
  鉴权      : 已启用（1 条规则），页面使用 Basic 认证
  上传密钥  : /home/me/.config/gofs/keys.json
  用户表    : /home/me/.config/gofs/users.json
  防护      : 上传≤10GiB  打包≤200000条/50GiB  目录≤20000条  并发512  无进展超时2m0s  跨站校验on
```

启动后访问 `http://127.0.0.1:5000`。**对服务根有读写权限**的账号会在顶栏看到
**「设置」** —— 换数据目录、临时放宽上传上限都不需要重启
（见「服务设置（运行期）」；没开鉴权时人人都是管理员，因此入口直接可见）。

## 在线编辑文本

目录列表里可编辑的文件会显示「编辑」按钮，**点击文件名也能直接打开编辑器**。

### 支持范围

按扩展名与文件名识别（`internal/textfile`），覆盖 txt / log / md / markdown / rst /
html / vue / svelte / css / scss / less / js / ts / jsx / tsx / json / jsonc / yaml /
xml / svg / toml / ini / conf / properties / env / csv / tsv / sql / sh / bash /
py / go / java / kt / c / cpp / h / cs / rs / rb / php / lua / r / swift / dart /
tf / hcl / proto / graphql … 以及 `Makefile` `Dockerfile` `.gitignore` `.env` 等无扩展名文件。

判定分两步：

1. **列表阶段只看文件名**，不读内容——列举目录时不该产生大量磁盘 IO；
2. **打开时再做内容嗅探**：含 NUL 字节或大量非法 UTF-8 一律判定为二进制并拒绝，
   防止编辑器把图片当文本打开后再保存，把文件彻底毁掉。

### 编辑器能力

- 行号、`Tab` 缩进（多行选区整体缩进 / 反缩进）、回车自动延续上一行缩进
- `Ctrl/⌘ + S` 保存，`Esc` 关闭（有未保存改动会二次确认）
- 状态栏显示行数、字符数、换行风格、BOM、文件大小与修改状态
- 超过 5000 行自动关闭行号渲染，避免大文件把 DOM 撑爆

### 预览

| 类型 | 预览方式 |
| --- | --- |
| Markdown | 自研渲染器，支持标题 / **粗体** / *斜体* / 行内代码 / 围栏代码块 / 列表 / 任务列表 / 表格 / 引用 / 分隔线 / 链接 / 图片 |
| HTML | `iframe sandbox=""`（**禁止脚本、禁止同源**，否则预览自己上传的 HTML 会让其中的脚本拿到凭据） |
| JSON | 格式化 + 语法着色，非法时指出解析错误 |
| XML | `DOMParser` 结构校验，非法时指出出错位置 |

Markdown 渲染前先对所有文本做 HTML 转义，链接还会过滤 `javascript:` / `data:` 协议。

### 安全与一致性

**乐观锁用内容摘要而非时间戳。** 打开文件时返回 `hash`（SHA-256 前 16 位），
保存时带上；服务端比对当前内容摘要，不一致返回 `409` 并附带 `current_hash`，
由用户决定是否强制覆盖。用时间戳会在「同一毫秒内两次保存」时误判。

**换行风格会被保留。** 浏览器的 `<textarea>` 提交时会把 CRLF 规范化成 LF，
若直接写回，Windows 换行文件的每一行都会变，在 git diff 里表现为整个文件被改。
服务端检测原文件风格并在写回时还原。

**BOM 会被保留。** 读取时剥离 UTF-8 BOM 交给编辑器，写回时重新加上。
UTF-16 编码的文件直接拒绝编辑（客户端无法正确处理）。

**写入是原子的。** 先写同目录临时文件再 `rename`，不会出现写到一半的残缺文件。

### API

```bash
# 读取
curl -u admin:123 'http://127.0.0.1:5000/__gofs__/text?path=/README.md'

# 保存（base_hash 来自读取响应）
curl -u admin:123 -X PUT http://127.0.0.1:5000/__gofs__/text \
  -H 'Content-Type: application/json' \
  -d '{"path":"/README.md","content":"# 新内容\n","base_hash":"3bca2438f174ef9a"}'

# 冲突时强制覆盖
curl -u admin:123 -X PUT http://127.0.0.1:5000/__gofs__/text \
  -H 'Content-Type: application/json' \
  -d '{"path":"/README.md","content":"...","base_hash":"...","force":true}'
```

## 上传密钥

给脚本或第三方一个**只能上传**的凭证，不用交出账号密码。

登录后点顶栏「密钥」即可管理。密钥的能力被刻意收得很窄：

| 能做什么 | 不能做什么 |
| --- | --- |
| `PUT` / `POST` 上传文件到指定目录 | 读取目录列表或文件内容 |
| 受日期归档规则约束 | 删除、重命名、新建目录 |
| — | 解压压缩包、在线编辑、管理其它密钥 |

最后一条尤其重要：**密钥不能用来管理密钥**，否则一把只能传文件的凭证
就能给自己签发新凭证，等于权限提升。

### 有效期

创建时可选 1 小时 / 6 小时 / 1 天 / 7 天 / 30 天 / 永不过期。
列表里显示每把密钥的状态、剩余时长、最后使用时间与使用次数，可随时撤销。

### 安全设计

- **明文只显示一次**。服务端只保存 `SHA-256(明文)`，`keys.json` 泄露也无法直接使用。
  界面上只展示可读前缀（`gofs_AbCd1234…`）供人工核对。
- **密钥文件权限 0600**，默认放在用户配置目录（`~/.config/gofs/keys.json`），
  不放在服务目录里——否则它会出现在自己的目录列表中。
- **校验用定长时间比较**，避免通过响应耗时逐字节猜测。
- **创建者的权限是上限**：签发时会检查调用者对该目录是否有写权限，
  只对 `/docs` 有权限的账号签不出覆盖 `/` 的密钥。
- **作用范围在归一化路径上比对**，`//uploads`、`/uploads/../etc` 这类写法绕不过去。

### 用法

```bash
# 上传（推荐用请求头）
curl -T backup.tar.gz \
  -H 'X-Gofs-Upload-Key: gofs_xxxxxxxx' \
  http://127.0.0.1:5000/incoming/backup.tar.gz

# 或写在查询参数里，便于一行搞定
curl -T backup.tar.gz 'http://127.0.0.1:5000/incoming/backup.tar.gz?key=gofs_xxxxxxxx'
```

失败时：密钥无效或过期返回 `401`，超出允许目录返回 `403`。

### API

```bash
GET    /__gofs__/keys                 列出全部密钥（不含明文）
POST   /__gofs__/keys                 创建，body {"name","scope","ttl_seconds"}
                                      响应中的 token 只返回这一次
DELETE /__gofs__/keys?id=<id>         撤销
```

## 认证

页面使用 **HTTP Basic 认证**，但不依赖浏览器原生登录框。

原生框有几个毛病：无法登出（凭据被浏览器缓存，通常要重启浏览器才失效）、
无法承载「登录后回到原页面」这类逻辑、移动端体验差、样式与应用割裂。
所以这里由应用自己弹登录框，凭据存在 `sessionStorage`（勾选「记住我」则存
`localStorage`），每次请求通过 `Authorization` 头带上。

### 未登录时的三种行为

| 请求类型 | 行为 | 原因 |
| --- | --- | --- |
| 浏览器导航目录（`Accept: text/html`，无 API 参数） | 返回**应用外壳** `200`，带 `auth_required: true` | 前端才有机会弹自己的登录框 |
| 应用内部请求（带 `X-Gofs-Ajax: 1`） | `401`，**不带**挑战头 | 避免弹出原生框打断应用流程 |
| 直接访问文件（如 `/a.txt`） | `401` + `WWW-Authenticate` 挑战 | 这时原生框反而是最自然的 |

外壳里**不含任何真实数据**：目录列表是空的，权限位全为 false，
上传归档等配置也不下发，未登录者拿不到任何文件名或目录结构。

### 刷新页面为什么不用重新登录

浏览器不会因为我们用 JS 把凭据存进 `sessionStorage` 就自动给页面请求加
`Authorization` 头。所以按 F5 时，服务端拿到的仍是一个**没有凭据的普通导航**，
只能返回空壳——里面既没有用户名、权限位也全是 false。

前端的处理是：

1. 页面加载时立刻从 `sessionStorage` / `localStorage` 读出凭据，
   **先用里面的用户名把界面填上**（否则会闪出「匿名」，登出按钮也会消失）；
2. 调一次 `GET /__gofs__/auth?path=<当前路径>`，用本地凭据换回真实的身份、
   权限与配置，然后用这些重新渲染；
3. 如果这一步返回 `401`，说明凭据已失效 —— 清掉本地存储并弹出登录框。

**登录成功后同样不做页面跳转**，而是前端自己 `fetch` 数据渲染 ——
跳转会陷入「跳转后浏览器不带凭据」的死循环。

### 受限账号在子目录里也能拿到完整按钮

`/__gofs__/auth` 支持 `?path=` 参数，按指定路径计算权限。
一个只被授予 `/docs:rw` 的账号，站在 `/docs` 里应该看到完整的操作按钮，
而不是被当成只读——不传 `path` 时才按根目录计算。
路径里含 `..` 会被直接忽略，不会借机提升权限。

### 命令行

`curl -u user:pass` 照常可用；`--anyauth` 也能走挑战流程。

## 用户与权限

账号有两个来源，页面上分得很清楚：

| 来源 | 怎么改 | 密码存法 |
| --- | --- | --- |
| **启动参数**（`-a` / `GOFS_AUTH`） | 只能改命令行后重启；页面上标「来自启动参数」，不可编辑 | 明文写在命令行里（本来就是你自己填的） |
| **用户表**（`users.json`） | 登录后点顶栏**「用户」**，随时增删改 | **PBKDF2 摘要**，服务端也拿不回明文 |

两边合并后一起参与匹配；**同名时以启动参数为准**（而不是启动失败 ——
用户表文件可能比命令行先存在，谁对谁错很难说，但「命令行是权威」简单且不会卡住服务）。

### 权限模型

沿用命令行那套「路径 → 权限」，**按最长前缀匹配，未命中的路径一律拒绝**：

```
alice 的规则： /docs 可读写　/ 只读
  → /docs/a.txt      可读写
  → /docs2/a.txt     只读（前缀按「目录段」匹配，/docs2 不是 /docs 的子路径）
  → /other/a.txt     只读
```

界面上就是一列「路径 + 权限」行，可以加多行。想给某人「只有某个目录能写、
其他位置能看」，就是上面这两行。

### 安全设计

- **密码只存摘要**：PBKDF2-HMAC-SHA256，21 万轮 + 每用户独立随机盐，
  32 字节派生密钥。落盘文件权限 `0600`，写盘走「临时文件 + rename」。
- **定长时间比较**，避免按耗时逐字节猜摘要。
- **验证明文永不出现在响应里**：接口只返回用户名、规则与时间戳。
- **改密码立刻生效**：密码校验有一层结果缓存（见下），任何改动都会整体清空它，
  否则旧密码会因为命中缓存而继续有效。
- **只有管理员能用**：判定与「服务设置」完全一致（对服务根有读写权限），
  与界面入口的显隐共用同一套条件，避免「按钮在但点了 403」。
  连账号列表都不给非管理员看 —— 账号名本身也是信息。
- **启动参数里的账号不可删改**：想摘掉就去改命令行。
- **防呆**：如果一次改动会**带走最后一个对根目录可读写的账号**，会被拒绝，
  并说明原因。否则就再没有入口能管理了。
- **未启用鉴权的部署不允许建用户**：那种情况下加第一个用户的副作用是
  「所有人立刻要登录」——包括正在操作的你。必须先用 `-a` 配一个账号。

### 为什么密码校验要带缓存

HTTP Basic 意味着**每个请求都要验一次密码**，而 PBKDF2 是按「故意很慢」
设计的（21 万轮 ≈ 100ms）。真按这个算，每个请求都要多花 100ms，服务基本不可用。

所以有一层「用户名+密码摘要 → 是否匹配」的内存缓存（上限 512 条，
键是 `SHA-256(用户名 + \0 + 密码)`，所以内存里也不留明文）。
首次校验某个组合时算一次 PBKDF2，之后直接命中。
任何一次用户表改动都会清空整个缓存 —— 这是「改密码立刻生效」的保证。

### API

```bash
# 列出账号（管理员）
curl -u admin:secret http://127.0.0.1:5000/__gofs__/users

# 新建：alice 在 /docs 可读写、其他位置只读
curl -u admin:secret -X POST -H 'Content-Type: application/json' \
  -d '{"name":"alice","password":"alice123","rules":[
        {"path":"/docs","perm":"rw"},{"path":"/","perm":"r"}]}' \
  http://127.0.0.1:5000/__gofs__/users

# 改权限（省略 password 就是不改密码）
curl -u admin:secret -X PUT -H 'Content-Type: application/json' \
  -d '{"name":"alice","rules":[{"path":"/docs","perm":"r"}]}' \
  http://127.0.0.1:5000/__gofs__/users

# 删除
curl -u admin:secret -X DELETE \
  'http://127.0.0.1:5000/__gofs__/users?name=alice'
```

`perm` 取 `"rw"`（可读写）或 `"r"`（只读）。响应始终是更新后的完整列表，
前端一次往返就能刷新。错误一律是 `400` + 可读的说明
（重名、密码太短、路径含 `..`、同路径重复、来自启动参数、最后一个管理员…），
界面会直接把这段文字显示出来。

### 落盘

用户表默认在 `<用户配置目录>/gofs/users.json`，可用 `--user-file` 改；
置空则只保存在内存中（重启即失效）。

```json
{
  "version": 1,
  "users": [
    {
      "name": "alice",
      "salt": "IBi1OQXu6BcAFSRc51ZrPw==",
      "hash": "qwTkyz7qePzE3slyT/fQT3btH8t+NlNa/XEykY+ogxw=",
      "iter": 210000,
      "rules": [{ "path": "/docs", "perm": "rw" }, { "path": "/", "perm": "r" }],
      "created_at": 1790604599,
      "updated_at": 1790604599
    }
  ]
}
```

文件损坏、账号非法（用户名带空格、没有任何路径权限、摘要字段缺失）、
或 `version` 高于本程序支持的版本时，**启动会直接失败并说明原因**，
而不是静默降级 —— 一个悄悄少了管理员的部署比启动不了更糟。

## 服务设置（运行期）

以前「换数据目录」「放宽上传上限」都得改启动参数再重启进程。现在登录后点顶栏的
**「设置」**，两件事都能在页面上直接改，**立刻生效、不用重启**：

| 项目 | 说明 |
| --- | --- |
| 服务根目录 | 换一个目录继续服务；填相对路径表示「从当前根再往下走」 |
| 单文件上传上限 | 数值 + MiB/GiB/TiB 单位；也可勾「不限制」；一键「恢复启动时的默认值」 |

入口只对**对服务根拥有读写权限**的账号可见（服务端还会再校验一次，
见下方「权限」）。

### 可切换的范围

根目录不是想切到哪就切到哪。默认**只能切到启动根目录的同一层**：

```bash
gofs -A /srv/data                 # 默认可切范围 = /srv/*（启动根的父目录）
gofs -A --root-allow /home/me -A /srv/data   # 额外放开 /home/me/*
gofs --no-root-switch -A /srv/data           # 完全禁止运行期切换
```

越界的路径一律 `400`，不会「先把根换掉再报错」。这几类写法会被直接拒绝：

- 目标不存在、不是目录、或为空
- 含 `..` 的路径（`/srv/data/../data` 也会被拒，不做静默归一化后再放行）
- 解析后落在允许前缀之外
- 符号链接指向允许范围之外

### 权限

`PUT /__gofs__/settings` 要求请求者在**服务根 `/`** 上具有读写权限：

- 没有任何凭据 → `401`
- 有凭据但没有根目录读写权限 → `403`
- 上传密钥不能用来改设置（密钥只有上传能力）

### API

```bash
# 读取当前设置
curl -u admin:secret http://127.0.0.1:5000/__gofs__/settings

# 切换根目录
curl -u admin:secret -X PUT -H 'Content-Type: application/json' \
     -d '{"root":"/srv/other"}' http://127.0.0.1:5000/__gofs__/settings

# 上传上限改成 2 GiB（0 表示不限制）
curl -u admin:secret -X PUT -H 'Content-Type: application/json' \
     -d '{"upload_max_size":2147483648}' http://127.0.0.1:5000/__gofs__/settings
```

响应体：

```json
{
  "root": "/private/tmp/gofs-test",
  "root_switchable": true,
  "allow_roots": ["/private/tmp"],
  "upload_max_size": 10737418240,
  "upload_max_size_default": 10737418240,
  "upload_max_size_unlimited": false,
  "upload_date_dir": "2026/09/28"
}
```

`upload_date_dir` 就是拖拽上传会落到的日期目录（见下一节），前端直接拿它做提示。
`upload_max_size` 为 `0`（等价于 `upload_max_size_unlimited: true`）表示不限制。
写操作同样走**跨站来源校验**，`Origin: null` 会被 `403` 拒掉。

## 上传按年月日归档

**默认开启，但只对「直接传到服务根目录」的上传生效**：文件不会堆在根目录下，
而是自动放进 `年/月/日` 三级目录。

```
拖拽 photo.jpg 到根目录        →  /2026/09/28/photo.jpg      ← 归档
拖拽 run.log  到 /projects/logs →  /projects/logs/run.log    ← 子目录，原地放
```

**为什么只归档根目录**：根目录是「一堆散文件」的场景，按日期分三级最有用；
而子目录本身通常已经是有意义的分层（项目名、月份、业务线、某个相机的上传目录…），
再往里套一层年/月/日 只会让目录越陷越深，找文件时反而要点更多层。

设计上的几点考虑：

- **判据是「目标文件的父目录就是服务根」**，与服务端的实际写法一一对应
  （`path.Dir("/a.txt") == "/"` 归档；`path.Dir("/sub/a.txt") == "/sub"` 不归档）。
  前端三处提示（常驻投放区 / 上传按钮提示 / 页脚）用的是同一套判断 ——
  **提示与实际落盘不一致，比不提示更糟**。
- **连续拖拽不会越陷越深**。上传完成后页面停留在原目录（不会跳进日期目录），
  否则第二次拖拽就会生成 `2026/09/28/2026/09/28/`。
- **上传前会明确告知落点**。投放区、拖拽浮层、上传弹窗都写出实际目录，
  只有真的会归档时才追加「（按日期自动归档）」；上传完成的提示带一个「查看」按钮。
- **权限按最终路径复核**。路径重写后会重新走一遍 ACL 判定，避免绕过路径级权限。

### 自定义布局

`--upload-date-layout` 接受任意 Go 时间布局字面量：

```bash
gofs --upload-date-layout "2006/01/02" ./data   # 年/月/日（默认）
gofs --upload-date-layout "2006-01-02" ./data   # 2026-09-28
gofs --upload-date-layout "2006/01" ./data      # 只到月份
gofs --upload-date-layout "2006/01/02/15" ./data # 再加小时
gofs --no-upload-dated ./data                   # 关闭，文件一律落在目标目录
```

布局会在启动时用参照时刻试格式化做校验，含 `..`、绝对路径、反斜杠或冒号的写法会被直接拒绝。

### 单次覆盖

需要时可以在一次请求里覆盖默认行为：

| 参数 | 效果 |
| --- | --- |
| `?dated=0`（`false` / `no` / `off`） | 跳过归档，文件落在指定路径 |
| `?dated=1`（`true` / `yes` / `on`） | **强制归档**，即使在子目录里也按日期建目录 |

```bash
# 脚本要精确指定落点
curl -T local.txt 'http://127.0.0.1:5000/direct.txt?dated=0'

# 某个子目录（比如相机上传目录）仍想按日期分层
curl -T photo.jpg 'http://127.0.0.1:5000/inbox/photo.jpg?dated=1'
```

表单上传用同名字段：`dated=0` / `dated=1`。

### 响应头

`PUT` 成功后会返回文件真实落盘的路径，方便脚本确认位置：

```
HTTP/1.1 201 Created
X-Gofs-Path: /projects/logs/2026/09/28/run.log
X-Gofs-Offset: 2048
```

`X-Gofs-Path` 是百分号编码的（HTTP 头只能承载 ASCII），中文文件名不会变成乱码：

```
X-Gofs-Path: /2026/09/28/%E6%8A%A5%E5%91%8A.pdf
```

## 上传文件夹

**整个目录连同层级一起传上去**，不用先在服务端手动建目录。两个入口：

| 入口 | 说明 |
| --- | --- |
| 顶栏「文件夹」按钮 | 打开系统的目录选择框（`<input webkitdirectory>`），选中一个目录即可 |
| 直接把文件夹拖进页面 | 拖拽比选择框更顺手，且**可以一次拖多个目录** |

两个入口最终都收敛成「一组带相对路径的文件」，后面的上传逻辑完全共用。

```
拖 proj/ 到根目录  →  /proj/readme.md
                      /proj/src/main.go
                      /proj/src/util/helper.go
```

（上面是站在根目录的情况；归档规则见上一节 —— 站在子目录里拖文件夹就是原地放。）

实现上有几个不得不注意的点：

- **拖拽目录只有一条路能拿到结构**：`DataTransferItem.webkitGetAsEntry()`。
  `dataTransfer.files` 里根本没有目录内容，所以拖文件夹时只能走 entry 递归。
  另外 `DataTransferItemList` **只在事件派发期间有效**，任何 `await` 之后都会失效 ——
  必须先同步取出 items 并调用 `webkitGetAsEntry()`，再去异步遍历。
- **`readEntries` 要循环调用到空**。规范允许一次只返回一批（Chromium 是 100 条），
  只调一次的话大目录会静默漏文件。
- **路径在下发前清洗一遍**：丢掉空段、`.`、`..`，以及含反斜杠或冒号的段。
  正常来源不会命中（浏览器给的相对路径是安全的），但这是从「用户设备上的文件名」
  拼出来的，值得挡一道。
- **`.DS_Store` 之类不会被特殊处理** —— 拖什么传什么，不做魔法过滤。

### 传文件夹时的进度与并发

- 进度弹窗标题变成「上传文件夹」，正文显示 **`3/57　proj/src/main.go`** ——
  只看百分比的话，一个大目录根本不知道进行到哪了。
- **并发 3 个请求**。传文件夹时绝大多数是几 KB 的小文件，串行的话每个都要等一个
  RTT，几百个文件会慢得离谱；3 是折中值（远低于服务端的并发闸门，速度读数也还稳）。
- **超过 200 个文件先确认一次**，免得手滑把整个 home 目录拖进来。
- **点右上角 ✕ 可以中途取消**：正在排队的文件不再开始，已传的保留，
  提示里如实写出「已上传 X/Y，余下 N 个未上传」。
- **失败汇总成一条**，列出前几个具体原因。传文件夹时失败很容易成片出现，
  逐个弹提示会把界面刷爆。

### 已知限制

**空目录不会被创建**（`a/b/` 里一个文件都没有时，`a/b/` 不会出现在服务端）。
目录选择框和拖拽 API 都不会把空目录作为条目交出来，要支持就得额外发一次 `MKCOL`。
只包含子目录的中间层不受影响 —— 它们会因为下级文件的路径而被自动创建。

## 打包下载

顶栏的「打包下载」按钮有两种行为，取决于当前有没有勾选条目：

| 当前状态 | 按钮文案 | 打包内容 | 下载文件名 |
| --- | --- | --- | --- |
| 未勾选任何条目 | 打包下载 | 当前目录的全部内容 | `<目录名>.zip` |
| 勾选了 N 项 | 打包所选 (N) | 只有勾选的条目 | 单项 `<名字>.zip`，多项 `<目录名>-selected.zip` |

勾选目录时会**递归**打包其内容（包内保留目录本身作为条目，解压后结构不变）。
因此「不勾选直接打包」与「全选后打包」得到的结果是一致的 —— 测试里专门做了这项对照。

### HTTP API

```bash
# 打包整个目录（默认）
curl -OJ 'http://localhost:5000/docs?zip'

# 只打包选中的条目：GET 用重复的 pick= 参数
curl -OJ 'http://localhost:5000/docs?zip&pick=/docs/readme.md&pick=/docs/guide.txt'

# 选中很多时用 POST，避免 URL 超长（浏览器侧走的就是这条）
curl -OJ -X POST 'http://localhost:5000/docs?zip' \
  -H 'Content-Type: application/json' \
  -d '{"picks":["/docs/readme.md","/docs/sub"]}'
```

`pick` 以 `/` 开头时按「相对服务根」解析，否则按「相对当前目录」解析。
不支持逗号分隔 —— 文件名本身可以含逗号，切分会造成歧义。

响应头：

```
X-Gofs-Archive-Mode: all | picked      # 打包的是全部还是所选
X-Gofs-Archive-Entries: 11             # 包内条目数
X-Gofs-Archive-Bytes: 2099             # 原始字节数
X-Gofs-Archive-Skipped: 2              # 被跳过的选中项数（仅 picked 模式）
```

### 安全设计

每个选中项都要过三关，任一不过就被跳过（通过 `X-Gofs-Archive-Skipped` 告知，
前端会提示「有 N 项被跳过（不存在或没有读取权限）」）：

1. **不含 `..`** —— 显式拒绝。`path.Clean` 会把 `../../a` 静默改写成 `a`，
   虽未真正逃逸，但掩盖了调用方的意图（与解压侧的处理保持一致）
2. **能解析到服务根之内** —— 由路径解析器拦掉越界与符号链接逃逸
3. **逐项复核读权限** —— 路径级 ACL 同样生效，不能借打包把没权限的内容带出去

全部选中项都不可用时返回 **400**（而不是给一个空 zip），便于排查路径写错。

刻意**不**要求选中项必须位于当前目录之下：站内搜索是跨目录的，
强制落在当前目录会把「搜索后打包所选」这个用法直接堵死。权限由逐项复核保证，
包内路径优先取「相对当前目录」，不在其下的（搜索命中）退回「相对服务根」，
避免同名文件互相覆盖。

软链接一律不打包（可能指向服务根之外）。

## 压缩包在线解压

### 网页上用

1. 目录列表里带「可解压」标记的文件，右侧会多出 **解压** 和 **内容** 两个按钮
2. **内容** → 弹出压缩包清单，可逐个「取出」单个文件（不落盘，流式读取）
3. **解压** → 填写目标目录，确认后弹出实时进度条

### HTTP API

**列出压缩包内容**

```bash
curl 'http://127.0.0.1:5000/__gofs__/extract?path=/backup.zip'
```

响应：

```json
{
  "path": "/backup.zip",
  "format": "zip",
  "default_dest": "/backup",
  "total": 3,
  "entries": [
    {"name": "a.txt", "size": 12, "compressed_size": 14, "is_dir": false, "modtime": "2026-09-28T11:00:00+08:00"}
  ]
}
```

**取出包内单个文件（流式，不解压落盘）**

```bash
curl -O 'http://127.0.0.1:5000/__gofs__/extract?path=/backup.zip&file=a.txt'
```

**执行解压（SSE 进度流）**

```bash
curl -N -X PUT http://127.0.0.1:5000/__gofs__/extract \
  -H 'Content-Type: application/json' \
  -d '{"path":"/backup.zip","dest":"/restored","overwrite":false}'
```

返回 `text/event-stream`，逐条推送：

```
event: start
data: {"src":"/backup.zip","dest":"/restored","format":"zip","total":1203}

event: progress
data: {"current":"logs/2026-09/app.log","files":512,"dirs":8,"skipped":0,"bytes":8388608,"total":1203}

event: done
data: {"report":{"files":1203,"dirs":64,"bytes":104857600,"skipped":2,"warnings":["已跳过链接条目 ..."],"elapsed_ms":1840},"url":"/restored/"}
```

出错时推 `event: error`，并在 `data.partial` 里带上已完成的部分统计。

也支持用查询参数调用，方便一行 curl：

```bash
curl -N -X PUT 'http://127.0.0.1:5000/__gofs__/extract?path=/backup.zip&dest=/restored&overwrite'
```

### 安全设计

在线解压面对的是不受信任的输入，因此做了这几层防护：

| 风险 | 处理方式 |
| --- | --- |
| **Zip Slip**（`../../x` 写到目标目录外） | 每个条目路径先统一分隔符、拒绝绝对路径与盘符，再 `SafeJoin` 校验必须落在目标目录内；越界条目跳过并记入 `warnings` |
| **软链接逃逸**（tar 里的 symlink 指向 `/etc/passwd`） | `TypeSymlink` / `TypeLink` 条目一律跳过，不落盘 |
| **解压炸弹**（高压缩比 + 小体积） | 三重限制：条目数上限、写出总字节上限、单文件压缩比上限；实时累计，超限立即中止 |
| **权限位提权**（包内 4755 的 setuid 文件） | 忽略包内 mode，文件恒为 `0644`、目录恒为 `0755` |
| **路径歧义** | `dest` / `path` 中出现 `..` 段直接 400 拒绝，而不是静默规范化 |
| **覆盖已有数据** | 目标目录已存在且非空时必须显式 `overwrite=true`；非覆盖模式跳过同名文件 |
| **磁盘打满** | 写出过程用 `io.Writer` 包装器实时拦截，超限即熔断，不会先写满再检查 |

上限可通过 `--extract-max-total` / `--extract-max-files` / `--extract-max-ratio` 调整。

### 关于加密 zip

暂不支持。遇到 `zip` 的加密标记（general purpose bit 0）会直接返回明确错误，
而不是解出一堆损坏文件。如需支持可引入 ZipCrypto 解密。

### 关于中文文件名

`zip` 规范里文件名编码有歧义：Windows 上用 GBK 打包的 zip，Go 标准库不会自动转码。
本项目不引入第三方编码库以保持零依赖，因此这类 zip 的文件名可能显示为乱码
（`tar` / `tar.gz` 不受影响）。如需处理，可引入 `golang.org/x/text/encoding/simplifiedchinese`。

## 安全与防护

文件服务器最容易被击穿的三处是**磁盘、内存与文件描述符**。
下面这些默认值的目标是：被恶意使用时服务退化（返回 413 / 429 / 503），
而不是崩溃或把机器拖垮。全部可调，`0` 通常表示不限制。

### 大文件：能传多大，怎么保证传得完

**流式，不占内存。** 上传与下载都走固定缓冲的 `io.Copy`
（下载用 `http.ServeContent`），内存占用与文件大小无关。
实测 1 GiB 上传/下载各耗时 1 秒上下，进程内存无明显增长。

**超时按「有没有进展」算，不按总时长。** 这是支持大文件的关键取舍：

| 做法 | 后果 |
| --- | --- |
| 固定总时长（如「30 分钟必须传完」） | 10 GB 在 1 MB/s 的链路要 3 小时，会被硬生生掐断 |
| **无进展超时**（默认 2 分钟） | 只要还在传就一直续期，慢速大文件也能传完；只有真正停滞（连上不发/不读）才断开 |

实测：客户端每 0.5 秒读一块、总耗时 8 秒（阈值 2 秒）的慢速下载**完整传完**；
而连上后完全停止读取的连接会在阈值后被断开（读到残留数据后 EOF）。
上传同理 —— 停滞的连接会被及时释放，不占着并发名额。

**断点续传。** 上传中断后不必从头再来：

```bash
# 1) 首传（覆盖写）。中断后服务端留下的是本次内容的前缀
curl -T big.iso http://host/upload/big.iso
# 2) 问服务端已经有多少字节
curl -sI http://host/upload/big.iso | grep -i content-length
# 3) 从断点续传（服务端追加到末尾）
curl -X PUT -H 'X-Update-Range: append' --data-binary @<(tail -c +$((OFFSET+1)) big.iso) \
     http://host/upload/big.iso
```

安全性来自「首传是覆盖写」（`O_TRUNC`）：失败后残留的那部分**一定是本次的内容**，
接着往后写不会把别的文件拼进来。响应头 `X-Gofs-Offset` 是本次写入的字节数，
可以用它确认最终大小等于源文件大小。

**下载支持 Range**，所以客户端的续传、多线程下载、播放器拖动都是现成的。
前端上传大文件走的是 XHR `PUT`（流式直传），**不经 multipart 临时文件**，
所以不占额外的临时磁盘空间；网页端在中断后会自动按上面的协议续传。

### 上传防护

| 限制 | 默认 | 为什么 |
| --- | --- | --- |
| 单次上传字节数 | 10 GiB | 没有它，一个请求就能把磁盘写满 |
| 上传读超时（无进展） | 2 分钟 | 防「每秒发几个字节」的连接长期占名额 |
| 并发上传/解压任务 | 64 | 这两类操作长时间占连接与磁盘 IO |
| 文件名长度 | 255 字节 | 超长名交给文件系统会变成 500，提前拒绝更好 |

带 `Content-Length` 的超限请求会在**读任何数据之前**就被拒绝 —— 否则客户端
此时还在往外发数据，它收到的往往是连接重置，而不是那条 413 说明。
超限后若已写了半截文件会被清理掉（追加模式除外，那是续传的续接点）。

### 攻击面

**跨站写请求（CSRF）。** Basic 凭据由浏览器自动附带，恶意页面只要能让浏览器发一个
请求，就能借用户已登录的会话删文件。所以写方法（POST/PUT/DELETE/MKCOL/MOVE）会校验
`Origin`/`Referer` 与请求 Host 是否同源：

- 浏览器发起的跨站请求**一定**带这两个头之一 → 403；
- curl / 脚本这类非浏览器客户端通常不带 → 不受影响；
- 反向代理改写 Host 而保留 Origin 时可能误判，用 `--no-csrf-protect` 关闭。

**认证暴力破解。** Basic 认证可以被无限次尝试，按来源统计失败次数，
超过阈值（默认 10 次 / 5 分钟）后临时封禁并返回 429。
只有「带了凭据但不对」才算失败 —— 完全没带凭据只是未登录，
否则一个不带凭据的爬虫就能把正常用户的来源封掉。成功登录会清零计数。

**慢速攻击。** `ReadHeaderTimeout` 10 秒掐断「连上后慢慢发请求头」（Slowloris）；
请求头总量限制 64 KiB（标准库默认 1 MiB，请求头是每个连接都要缓冲的）。

**资源耗尽。**

| 面 | 限制 | 说明 |
| --- | --- | --- |
| 并发请求 | 512 | 兜住文件描述符与内存，取不到名额时短暂排队后返回 503 |
| 目录列举 | 20000 条 | 十万级文件的目录一次性序列化会吃掉大量内存；响应带 `truncated` 与 `total_all` |
| 打包 | 20 万条 / 50 GiB | 扫描阶段就累计检查，超限返回 413 而不是把内存撑爆 |
| 解压 | 10 GiB / 10 万条 / 200 倍压缩比 | 防解压炸弹；超限时清理残缺文件 |
| `?hash` | 512 MiB | 算摘要要读完整个文件，对超大文件开放等于送出一个 CPU/IO 耗尽入口 |
| 认证失败记录 | 惰性清理 | 避免被大量伪造来源撑爆内存 |

**存储型 XSS。** 文件服务器天然会把上传的 `.html` / `.svg` 原样吐回浏览器，
而浏览器会把它当作**本站页面**渲染 —— 一个能上传文件的人只要放一个
`<script>fetch('/__gofs__/keys',{method:'POST'…})</script>` 再诱导管理员打开，
就能借管理员的登录态为所欲为。所以：

- 所有文件响应带 `X-Content-Type-Options: nosniff`（禁止按内容猜类型）；
- HTML / SVG / XML 额外带 `Content-Security-Policy: sandbox`，
  页面仍可正常预览渲染，但里面的脚本读不到本站数据。需要连脚本一起预览时用
  `--no-html-sandbox`。

**日志注入。** URL、User-Agent 以及**文件名**都会进日志。文件名这一点容易被忽略 ——
Linux 上文件名可以含换行，于是 `rm -rf $'a\n127.0.0.1 - - "GET /admin" 200'`
这样一个名字就能在日志里伪造出额外一行。所有日志行在写出前会清理控制字符与 ANSI 转义。

## 界面细节

这些不是「有没有功能」的问题，而是「功能在不在用户眼前」的问题。逐条说明：

**① 拖拽上传要让用户看得见、也知道落到哪。**
只靠「拖到一半才出现的浮层」是不够的 —— 用户**开始拖之前**根本不知道这页支持拖拽。
所以有写权限时目录页底部常驻一块虚线投放区；文件拖进窗口后，再弹出全屏浮层。
**常驻区、拖拽浮层、上传弹窗、上传按钮的悬停提示**四处都会写明落点，
而且只有真的会归档时才追加「（按日期自动归档）」：

```
站在根目录（会归档）：
把文件或文件夹拖到这里即可上传
存入 /2026/09/28/（按日期自动归档）　·　单文件 ≤ 10.0 GiB      ← 常驻投放区
（右侧还有「选择文件…」「选择文件夹…」两个按钮）

松开即可上传
存入 /2026/09/28/　·　3 项　·　单文件 ≤ 10.0 GiB               ← 拖拽浮层

存入：/2026/09/28/（按日期自动归档）　·　单文件上限：10.0 GiB    ← 上传弹窗


站在子目录 /docs（不归档，原地放）：
把文件或文件夹拖到这里即可上传
存入 /docs/　·　单文件 ≤ 10.0 GiB
```

拖拽浮层还会实时给出**本次拖进来的条目数**（一个文件夹算 1 项，
展开后的真实文件数在上传弹窗里显示）；松手或离开窗口后浮层立刻收起。
归档规则见上文「上传按年月日归档」，文件夹上传见「上传文件夹」。

**② 所有弹窗的底部统一。** 从前是每个弹窗各自拼按钮，间距、对齐、按钮顺序都不一致，
「确定」有时在左有时在右。现在统一走 `G.modalFoot()`：
底部区在正文之外（有独立分隔线与背景）、**取消恒在左、确认恒在右**，
危险操作（删除、放弃未保存的修改、取消上传上限）用**实心红按钮**。

**③ 上传速度与剩余时间。** 进度弹窗显示「已传 / 总量（百分比）　·　1.2 MiB/s　·　剩余 8 秒」。
速度用**指数平滑**（系数 0.35，采样间隔 ≥0.35s）算，而不是「已传字节 / 已耗时」——
后者在「先慢后快」时严重滞后，看着像卡住了；平滑系数是实测的折中（再大抖动明显，再小反应慢）。
速率没稳定到 4 KiB/s 以上之前不显示剩余时间，免得闪出一串离谱数字。

**④ 页脚说真话。** 页脚改为实时渲染（在 `renderPerms` 里调用，而不是启动时算一次）：
左边显示**当前真实账号与可写性**，右边列出**实际具备的能力**：

```
已登录 admin · 可读写　·　可上传 · 可删除 · 可在线编辑 · 可在线解压 · 上传归档到 2026/09/28/
未登录 · 只读
无需登录 · 可读写          （服务本身没开鉴权时不提「登录」，避免困惑）
```

登录后不会再残留「只读模式」这类过期状态。

**⑤ 运行期服务设置。** 见上文「服务设置（运行期）」。

**⑥ 上传上限可改。** 同上；启动参数给默认值，页面上按需覆盖。

**⑦ 操作按钮按功能区分颜色。** 行内按钮带 `data-kind`，CSS 为每个类别定义独立变量
（定义在 `:root`，深色主题另有覆盖，不是散落各处的硬编码色值）：

| 功能 | `data-kind` | 变量 | 浅色取值 |
| --- | --- | --- | --- |
| 打开 | `open` | `--op-open` | `#2563eb` 蓝 |
| 下载 | `download` | `--op-download` | `#0e7490` 深青 |
| 编辑 | `edit` | `--op-edit` | `#7c3aed` 紫 |
| 解压 | `unzip` | `--op-unzip` | `#b45309` 琥珀 |
| 内容（看压缩包清单） | `list` | `--op-list` | `#475569` 石板灰 |
| 重命名 | `rename` | `--op-rename` | `#0f766e` 青绿 |
| 删除 | `trash` | `--op-danger` | `#dc2626` 红 |

「更多」菜单（手机端）里的图标复用同一批颜色。另外操作区的常态透明度从 `0.35`
提到可辨识的水平（触摸设备上恒为不透明），不用再靠 hover 才能看清。

**⑧ 顶部统计的准确性。** 统计区分**两个口径**，并在 `title` 里写明：

- 未选中时：`3 个目录 · 8 个文件 · 文件合计 1.2 MiB` —— 这是**整个目录**的规模。
  目录数与文件合计来自服务端全量统计（`dir_count` / `file_size`），
  **即使列表被截断也算得准**，并在末尾额外标注
  `已截断：该目录共 20000 项，仅列出前 20000 项`；
- 选中后：在这个口径**之前再叠加**一段
  `已选 2 项（1 个目录 · 1 个文件 · 34 KiB）　/　`，而不是把目录规模替换掉。

这样「选中几个文件想删掉」时，两个数字都能读到自己的意思。

### 目录导航：地址栏与并发点击

目录切换是 `fetch` + `history.pushState` 做的（不整页跳转）。这里有两个
「只在特定条件下才暴露」的坑，都已修掉并被回归测试盯住。

**① 根目录的 URL 不能拼成 `//`。** 从前写的是 `pushState(..., fileURL(path) + '/')`，
而根目录的 `fileURL('/')` 本身就是 `'/'`，拼出来是 `'//'` —— 浏览器把它当
**协议相对 URL**（scheme-relative），解析成 `http:` 加一个空主机，于是：

```
Failed to execute 'pushState' on 'History':
A history state object with URL 'http:' cannot be created in a document with
origin 'http://127.0.0.1:5000' ...
```

它还在 `navigate` 的 `try` 里，异常被当成「打开目录失败」，`render()` 根本没执行 ——
**目录其实已经取回来了，却卡在原地并弹一个误导的错误**。
现在用一个 `dirURL()` 保证「恰好一个结尾斜杠」，并且地址栏更新单独包了 `try`：
**它只是锦上添花，任何原因失败都不该拖垮这次导航**。

**② 导航途中的点击不能被静默丢弃。** 从前是 `if (state.busy) return;`。
用户点「根目录」的那一刻，如果恰好有一次「上传完成后的列表刷新」在途
（很常见），这次点击就**白点了**：地址栏不动、列表不动、也没有任何提示。
现在改成**排队**：记下最后一次请求，等当前导航结束后补跑；
被后一次取代的那次会立刻以 `false` 结束，免得调用方一直等下去。

```js
const p1 = navigate('/docs');   // 在途
const p2 = navigate('/');       // 排队
const p3 = navigate('/docs');   // 取代 p2 → p2 立刻拿到 false
// 最终停在 /docs，p1/p3 为 true
```

排查这类问题可以在浏览器控制台打开 `window.__navDebug = true`，
每次导航都会打印目标路径与**调用来源**（含调用栈），比单步断点快得多。

## 与 dufs 的差异

| 项 | dufs | gofs |
| --- | --- | --- |
| 语言 | Rust | Go |
| 在线解压 | 仅支持目录打包下载 | 支持 zip / tar / tar.gz / gz 的解压、预览、单文件取出 |
| 解压进度 | — | SSE 实时推送 |
| 在线编辑 | 支持（简单文本框） | 支持，带行号、Markdown/HTML/JSON/XML 预览、摘要乐观锁、换行与 BOM 保留 |
| 上传密钥 | — | 支持，可限目录 / 设有效期 / 撤销，只存摘要 |
| 用户管理 | 仅命令行 `-a` | 命令行 + **页面上增删改**，密码只存 PBKDF2 摘要，落盘 users.json |
| 登录体验 | 浏览器原生 Basic 弹窗 | 应用内登录框（仍是 Basic 协议） |
| 上传归档 | — | 传到根目录时按 年/月/日 三级目录归档（子目录原地放），可自定义布局、可单次覆盖 |
| 文件夹上传 | — | 支持（选目录 / 拖目录），保留完整层级；带进度、可中途取消 |

# 终端 A：以鉴权模式启动（admin 可写根，test 只读）

- 预览面板能展开并产出内容
- **编辑后未保存时，退出 / 右上角 ✕ 都会弹出确认框**（点取消改动仍在，点放弃才关闭）
- **刷新页面后登录态保持**（用户名不会退化成「匿名」，凭据失效时回到登录框）
- **打包按钮随选中变化**：「打包下载」↔「打包所选 (N)」，且点击时分别发出
  GET（全部）/ POST（带 picks 的所选）请求
- **手机端「更多」菜单**：每行都有该按钮、点开后菜单项与行内按钮一一对应
  （同一份操作定义）、点选后菜单关闭
- **页脚与统计准确**：页脚显示真实账号与**实际具备的能力**（登录后不再显示
  「只读模式」）；统计同时给出目录数、文件数与合计大小，选中后再叠加「已选 N 项」
- **拖拽上传的可见性**：常驻投放区、拖拽浮层、上传弹窗三处都写明**文件会落到哪个目录**，
  并给出单文件上限；进度里带**上传速度**与剩余时间 / 总量
- **弹窗底部统一**：所有弹窗都走同一套 `.modal-foot`（取消在左、确认在右），
  破坏性操作用实心红按钮
- **操作按钮的语义色**：行内按钮带 `data-kind`，CSS 为 open / download / edit /
  unzip / list / rename / trash 各自定义独立颜色变量（不是硬编码）
- **服务设置面板**：能打开、能读到当前根目录与上传上限、给出可切换范围、
  单位下拉与「不限制」开关齐全
- **目录导航**：点目录名能进子目录（地址栏、面包屑、列表三者一致）、
  点「根目录」能回来且**没有报错**、地址栏链接不是协议相对 URL（`//…`）、
  复杂点：**导航途中的再次点击不会被丢掉**（队列里只留最后一次）
- **归档只在根目录生效**：站在根目录时三处提示都写日期目录并标注「按日期自动归档」、
  页脚显示「上传归档到 …」；进子目录后这些提示全部消失、投放区指向子目录本身
- **文件夹上传**：两个入口都在（顶栏「文件夹」按钮 + 投放区「选择文件夹…」）、
  目录输入框带 `webkitdirectory`、点按钮打开的是目录框而不是文件框；
  选目录后**发出的 PUT URL 保留了目录层级**；拖拽目录走
  `webkitGetAsEntry` 递归（含「`readEntries` 分批返回」这条必须循环取完的路径）
- **用户与权限**：入口只对管理员可见、启动参数的账号标「来自启动参数」且不可编辑、
  权限以胶囊逐条列出、匿名访问单独说明；新建表单（密码遮蔽 / 显示 / 随机生成、
  权限行增删）、**发出去的请求格式**（POST + 结构化 rules、编辑时不带 password）、
  删除前必须确认且用实心红按钮
- **顶栏「更多」折叠菜单**：6 个低频操作都在面板里且**没有被 `hidden` 掉**
  （折叠是布局、隐藏是权限，两件事不能混）、展开后 `aria-expanded=true`、
  再点一次 / 点面板外 / 按 Esc 三条关闭路径、点菜单项后自动收起、
  不会顺带留下别的弹窗
- **窄屏文案**：临时给 `matchMedia` 打桩模拟 560px 屏，断言统计换成
  `N 目录 · N 文件`、页脚去掉「已登录」且能力改短词、投放区一行说得完；
  还原之后长口径文案又回来（说明两套都活着，不是把一套删了）
- **跨模块接口完整性**（`window.GOFS` 的 33 个约定接口逐个校验）
- **确认弹窗的返回值语义**（点「确定」必须得到 `true`，点「取消」得到 `false`）

> **为什么值得单独测这些：** 有三类 bug 只在特定路径上出现，`go vet`
> 和接口测试都发现不了，用户只会反馈“按钮点了没反应”：
>
> 1. **权限快照** —— 权限对象在脚本加载时被做成快照，登录后没更新，
>    导致除「下载」「打开」外的**全部按钮消失**，看起来像功能没实现；
> 2. **接口漏暴露** —— 某个 `G.xxx` 忘了赋值，调用处直接抛异常；
> 3. **确认弹窗返回值竞态** —— 按钮回调先 `close` 再 `resolve`，
>    `onClose` 里的 `resolve(false)` 抢先定值，用户点「确定」也只拿到 `false`，
>    于是「强制覆盖」「撤销密钥」全部静默失效。

上手改这个测试脚本时有两个容易踩的坑（都是实测踩出来的）：

- **挑元素要挑「能覆盖这条断言」的那个**，不是「第一个匹配正则的元素」。
  比如预览按钮只对 md/json/xml/html 出现，如果碰巧挑到目录里唯一的
  `.txt`，就会误报「预览功能坏了」；
- **合成点击事件的 `cancelable` 必须显式给 `true`**。
  `new MouseEvent('click', {bubbles: true})` 的 `cancelable` 默认是 `false`，
  `preventDefault()` 会失效，jsdom 会真的去导航，看起来像「应用没拦住默认跳转」。

### 手机端适配

页面在手机上不是「缩小版桌面」，几处交互按触摸设备的实际约束重做过。

**顶栏按「信息」与「动作」分两层。** 原来所有东西塞在一坨里自适应换行，
手机上折成 4 行（品牌 logo 自己一行 + 两行按钮 + 面包屑自己一行），
**顶栏高 205px，占掉 812px 屏幕的 25%** —— 首屏只看得见一条文件。
现在：

```
行1  [图标] 路径面包屑 ……………………  [账号]
行2  [搜索框] [刷新] [更多 ⌄] [上传]
```

| 宽度（触摸模拟） | 旧顶栏 | 新顶栏 |
| --- | --- | --- |
| 320px | 242px | **105px** |
| 375px | 205px | **105px** |
| 414px | 205px | **105px** |
| 560px | 194px | **105px** |
| 561px | 161px | **105px** |
| 768px | 111px | **105px** |

低频操作（主题 / 文件夹 / 新建 / 密钥 / 用户 / 设置）进「更多」下拉，
每项 46px 高、带图标与文字，一键可达。

**折叠只改布局，不改可用性。** 被收进菜单的按钮 `hidden` 属性照旧由权限控制，
菜单项也会跳过没权限的；「更多」按钮本身带文字（不是光秃秃一个 `⋯`），
否则「功能入口」看起来就像消失了 —— 这类误判在这个项目里出现过不止一次。
三个关闭路径都有：再点一次、点面板外、按 Esc；换目录时自动收起。

**为什么断点是 820 而不是 560。** 「顶栏放不下」是按钮数量问题，不是屏宽问题：
561px 时旧版要 161px、768px 时要 111px，都是被按钮数量顶上去的。
所以折叠的断点跟「面包屑占整行」的 820px 对齐，820 与 821 之间只差 4px，没有断层。

> **别踩的坑**：`.btn.icon` 在触摸设备上被固定成 `40×40`，特异度是 `(0,2,0)` ——
> 光靠「写在后面」压不住它，`.more-toggle { width: auto }` 会被吃掉，
> 结果「更多」二字被挤没。必须写成 `.btn.more-toggle` 同级对抗。

**统计 / 页脚 / 投放区在窄屏换短句，而不是靠截断。** 例如
`3 个目录 · 8 个文件 · 文件合计 54 KiB` → `3 目录 · 8 文件 · 54 KiB`；
页脚去掉重复的「已登录」与每个词前面的「可」；投放区那句
「把文件或文件夹拖到这里即可上传」在手机上是错的（手机不能拖拽），换成一行
`存入 /2026/09/28/ · 自动归档 · ≤ 10 GiB`，并且**搬到列表上方** ——
长列表下面的一行字等于不存在。

判据是 `window.matchMedia('(max-width: 560px)')`，封装在 `app.js` 的 `isNarrow()`。
⚠️ jsdom 没实现 `matchMedia`，直接调会抛异常把整页逻辑带崩，所以必须判空，
缺失时按宽屏处理（文案更完整的那个分支）。

**操作入口收进「更多」菜单。** 一行最多有 5 个操作（下载/解压/内容/重命名/删除），
行内平铺会把文件名挤到只剩 100px 出头，而且每个按钮都远小于可点尺寸。
所以 ≤560px 时行内只留一个 `⋯`，点开是占满宽度的操作列表（每项 48px 高）。
宽屏时这个按钮由 CSS 隐藏——**两种呈现共用同一份操作定义**，
不会出现「桌面点得到、手机点不到」的功能差异。

**触摸目标一律 ≥40px。** 顶栏图标按钮 32→40、操作按钮、勾选框（用 `label`
把整格变成可点区域）、品牌 logo、面包屑、文件名（加垂直留白）。
判据分两级：按钮类要求两个方向都够大，文字链接只要求高度
（`.env` 这种文件名天然很窄，强求宽度没意义）。
勾选列刻意**不**收窄：它的可点区域是整格，一收窄就掉到 40px 以下
（实测 38×42 被判为「按不准」）—— 4px 的表格宽度不值得用「点不中」去换。

**底部安全区。** 页脚与弹窗在 `≤560px` 时给 `env(safe-area-inset-bottom)`
留位，免得被 iPhone 的底部横条压住。

**根除三类只在触摸设备上出现的毛病：**

| 症状 | 原因 | 做法 |
| --- | --- | --- |
| 操作按钮看不清 | `.ops` 靠 `tr:hover` 才变不透明，触摸设备没有 hover | `@media (hover: none)` 下恒为不透明 |
| 整页横向溢出 60px | `.topbar-actions` 是 flex 项目，默认不缩到比内容窄，内部换行没机会生效 | 加 `min-width: 0` + 内部 `flex-wrap`（**所有宽度**都生效，见下） |
| 输入框一聚焦页面就放大 | iOS 对 `font-size < 16px` 的输入框会自动缩放，且很难缩回去 | 触摸设备下输入框与编辑器统一 16px |

改编辑器字号时**必须同步改行号栏**：两者共用 1.65 行高，只改一边会让行号与代码
逐行错开（`editor.js` 只用 `scrollTop` 同步滚动，没有硬编码行高，所以调字号是安全的）。

**顶栏按钮变多会撑破中等宽度。** 这条一开始只写在手机断点里 —— 当时只有 4 个按钮，
561px 以上一行放得下。加到 6 个（上传 / 文件夹 / 新建 / 密钥 / 用户 / 设置）之后，
**561px 与 900px 都溢出**（分别 37px / 45px）：`.topbar-actions` 在那些宽度下仍是
`flex: none`，绝不缩到比内容窄，于是把整页撑出横向滚动条。
所以「允许换行 + `min-width: 0`」已经提到**基础规则**里，不再挂在手机断点下 ——
顶栏放不下是按钮数量问题，不是屏宽问题。

**回归命令：**

```bash
make touch-sweep     # 12 个宽度 × 触摸模拟：无横向溢出 / 目标 ≥40px / 无半透明
make touch-modals    # 单独校验编辑器、操作菜单、服务设置面板里的按钮
```

### 表格布局回归（真浏览器）

上面两个测试都碰不到**渲染后的几何**：列宽够不够、内容有没有画到隔壁单元格上，
是 CSS 与 `table-layout` 决定的，jsdom 不做布局计算。所以另有一个用 CDP 直连
headless Chrome 的测量脚本：

```bash
# 终端 A：起一个带调试端口的 headless Chrome
make cdp

# 终端 B：扫一遍所有响应式断点
make layout-sweep          # 或单测一个宽度：make layout W=1280
```

每个宽度都会校验三件事，任一不过就退出码非 0：

1. **表头可见列数 == 数据行可见列数** —— 只给 `th` 加 `display:none` 而漏掉 `td`，
   `table-layout: fixed` 的列宽分配会整体错位（实测能把操作列从 196px 挤到 34px）
2. **操作按钮没有溢出自己的单元格** —— 溢出会直接画到「修改时间」列上
3. **按钮没有折行** —— 折行不覆盖，但行高会变大

加 `TOUCH=1`（或直接 `make touch-sweep`）时再补两条：**页面无横向溢出**、
**可点目标达到最小边长**、**可点元素不能是半透明**。

目标开了鉴权时用 `MEASURE_AUTH=user:pass make layout`。

两个额外开关（改动 UI 时很省事）：

```bash
# 想人眼复核排版，而不是只看数字
MEASURE_SHOT=/tmp/shot.png node scripts/measure-layout.mjs http://127.0.0.1:5001 1440 900

# 量弹窗内部的元素（编辑器 / 行操作菜单 / 服务设置面板）
MEASURE_OPEN=settings node scripts/measure-layout.mjs http://127.0.0.1:5001 375 812
```

背后的几条 CSS 约束（改动列宽前请先读）：

- `.op-btn` 有 `flex: none`，**不会被压缩**。最宽的一行是压缩包：
  下载 / 解压 / 内容 / 重命名 / 删除，实测需要 **318px**（图标模式下 166px），
  所以 `.col-ops` 在宽屏给 352px、窄屏给 196px；
  触摸设备上按钮被放大到 40px，图标模式要 216px，故再放宽到 252px。
- `.ops` 有 `flex-wrap: wrap` 兜底：宽度实在不够时折行，绝不允许压到相邻列。
- 手机宽度（≤560px）改用「更多」菜单，`.col-ops` 缩到 64px，把宽度还给文件名。

> 这条测量链路是有来历的：用户反馈「修改时间列和操作列重合」，
> 表面看只是列宽不够，量下去才发现是两个叠加的问题 ——
> 宽屏下 250px 的列装不下 318px 的按钮（向左溢出），
> 窄屏下隐藏时间列时只隐藏了 `th`，导致列数错位、整个表格的列宽分配都乱了。
